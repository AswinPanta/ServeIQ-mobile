# i18n — Internationalization Design

## Summary

Add full internationalization to the guest portal using `i18next` + `react-i18next` with `expo-localization` for device locale detection. 7 languages: English, Hindi, Nepali, French, Spanish, Japanese, Chinese Simplified.

## Architecture

### Libraries
- `i18next` — core translation engine (pluralization, interpolation, formatting)
- `react-i18next` — React/RN bindings (`useTranslation`, `I18nextProvider`)
- `expo-localization` — device locale detection (OS language, region)

### Initialization (`lib/i18n/index.ts`)
```ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import * as Localization from 'expo-localization';
import en from './locales/en.json';
import hi from './locales/hi.json';
// ... all 7 languages

i18n.use(initReactI18next).init({
  resources: { en: { translation: en }, hi: { translation: hi }, ... },
  lng: Localization.getLocales()[0]?.languageCode ?? 'en',
  fallbackLng: 'en',
  interpolation: { escapeValue: false },
  returnObjects: true,
});
```

### Language Persistence
- `PreferencesContext.language` stores user's language choice
- On app launch: check Preferences → fallback to device locale → fallback to 'en'
- When user changes language: update PreferencesContext + call `i18n.changeLanguage()`
- GuestFooter language selector becomes functional

## Translation Files

### Organization
```
lib/i18n/locales/
  en.json       — English (base, source of truth)
  hi.json       — Hindi (हिन्दी)
  ne.json       — Nepali (नेपाली)
  fr.json       — French
  es.json       — Spanish
  ja.json       — Japanese (日本語)
  zh-CN.json    — Chinese Simplified (简体中文)
```

### Key Convention
Dot notation grouped by screen area:
- `common.{key}` — shared strings (OK, Cancel, Back, Continue, Save, etc.)
- `auth.{screen}.{key}` — login, register, otp, forgot-password, etc.
- `home.{key}` — index/search tab
- `search.{key}` — search results
- `booking.{key}` — booking flow, summary, confirmation
- `profile.{key}` — profile screen and sub-pages
- `property.{key}` — property detail, room select
- `components.{component}.{key}` — shared guest components

### Pluralization
i18next built-in plural rules used for:
- `booking.nights` — "1 night" / "{n} nights"
- `booking.guests` — "1 Guest" / "{n} Guests"
- `search.properties` — "{n} properties" / "1 property"

## Integration

### app/_layout.tsx
Wrap with `I18nextProvider` around existing providers:
```tsx
<I18nextProvider i18n={i18n}>
  <AuthProvider>
    ...
  </AuthProvider>
</I18nextProvider>
```

### Language Switch Hook
```tsx
function useAppLanguage() {
  const { preferences, updatePreferences } = usePreferences();
  const { i18n } = useTranslation();

  const setLanguage = (lang: string) => {
    i18n.changeLanguage(lang);
    updatePreferences({ language: lang });
  };

  return { language: preferences.language, setLanguage, availableLanguages };
}
```

### Migration Pattern
Each file: import `useTranslation` → replace `<Text>...</Text>` with `<Text>{t('key')}</Text>`.
```tsx
// Before
<Text>Welcome back!</Text>
<Text>Email</Text>

// After
import { useTranslation } from 'react-i18next';
const { t } = useTranslation();
<Text>{t('auth.login.title')}</Text>
<Text>{t('auth.login.email')}</Text>
```
